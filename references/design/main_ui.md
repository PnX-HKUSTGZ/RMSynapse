# 自定义客户端主 UI 设计构思

本文记录自定义客户端“主 UI”的页面规划。主 UI 是操作手比赛中默认停留的页面，目标不是展示所有协议字段，而是在最短时间内回答几个关键问题：

- 当前比赛大势如何，基地、前哨站、机器人血量是否支持继续进攻或需要转火。
- 本机还能不能打，热量、弹量、锁发射机构、图传、血量是否安全。
- 当前是否有需要立即响应的事件，例如击杀、战亡、前哨站可重建、能量机关可触发、基地遭攻击。
- 当前能不能执行补血、补弹、复活、部署、姿态切换、空中支援、工程装配等操作。

## 1. 页面总结构

主 UI 采用“顶部全局态势 + 左侧告警 + 中央图传 + 右侧操作 + 右下小地图 + 底部本机/工程状态”的结构。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ A 顶部状态带：时间/阶段 + 基地/前哨 + 双方机器人血量 + 金币/链路状态          │
├───────────────┬──────────────────────────────────────────────┬───────────────┤
│ B 告警/事件流  │ C 图传主视野 + 准星热量环 + 弹量/锁定/Buff     │ D 角色操作区    │
│               │                                              │               │
│ E 模块状态图标 │                                              │ F 右下小地图    │
├───────────────┴──────────────────────────────────────────────┴───────────────┤
│ G 本机状态条 / 工程装配流程条                                                │
└──────────────────────────────────────────────────────────────────────────────┘
```

推荐 1920x1080 尺寸分配：

| 区域 | 建议尺寸 | 作用 |
| --- | --- | --- |
| 顶部状态带 | 1920 x 110~120 | 全局胜负态势、双方机器人血量、金币、链路状态 |
| 左侧告警区 | 280~320 x 760~800 | 当前告警、事件流、模块状态摘要 |
| 中央图传区 | 1180~1260 x 760~800 | 主视野、射击 HUD、热量环、弹量、锁定状态 |
| 右侧操作区 | 340~420 x 760~800 | 通用操作、角色专属操作、右下小地图 |
| 底部状态/工程条 | 120~180 高 | 本机底盘/缓冲/Buff；工程角色显示装配流程 |

## 2. A 顶部状态带

顶部状态带不让比赛时间独占过多空间，而是承担“全局态势条”的职责。操作手应能从这里直观看到是否继续倾泻火力、是否转火、是否集火低血量目标。

建议两行布局：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 比赛中 04:36 │ 己基地 4200+盾 │ 敌基地 3100 展开 │ 己前哨 0 可重建 │ 敌前哨 1500 │ 金币 620 │
│ 己 H 320 E250 I3 180 I4 0 S530 │ 敌 H120 E? I3 60 I4 0 S400 │ 链路 MQTT✓ 图传✓ │
└──────────────────────────────────────────────────────────────────────────────┘
```

第一行显示胜负目标：

- 比赛阶段和剩余时间。
- 己方基地血量、护盾、护甲状态。
- 对方基地血量、护盾、护甲状态。
- 己方前哨站血量、被击毁、可重建、重建中。
- 对方前哨站血量、被击毁、停转。
- 己方金币。
- MQTT、图传等核心链路状态。

第二行显示双方机器人血量横条：

- 己方英雄、工程、步兵、哨兵、空中状态。
- 对方英雄、工程、步兵、哨兵、空中状态。
- 已知血量显示数字和短血条。
- 未知血量显示 `?`。
- 数据过期时灰化并显示更新时间或过期标识。
- 关键标签：`LOW`、`DEAD`、`易伤`、`特殊标识`、`离线`、`复活中`。

顶部信息优先级：

1. 基地和前哨站状态。
2. 双方机器人血量，尤其是敌方低血量和己方战亡。
3. 金币和链路状态。
4. 比赛阶段和时间。

## 3. B 左侧告警/事件流

左侧不放队伍机器人列表，队伍和对方血量已经放到顶部。左侧作为“战术告警中心”，负责显示需要立即注意或短时间内决策的事件。

```text
┌────────────────┐
│ 当前告警        │
│ 前哨可重建 x2   │
│ 大能量可触发    │
│ 敌英雄低血量    │
│ 我方空中被照射  │
├────────────────┤
│ 事件流          │
│ 04:21 敌I4战亡  │
│ 04:18 我方前哨毁│
│ 04:12 基地被攻击│
│ 04:08 飞镖命中  │
└────────────────┘
```

当前告警最多显示 3 条，避免告警区本身过载。事件流保留最近 6~8 条即可。

告警分级：

| 级别 | 示例 | 表现 |
| --- | --- | --- |
| 高 | 本机血量极低、本机锁发射机构、图传断开、黄牌/红牌、基地遭攻击、前哨站被击毁、我方机器人战亡 | 红/橙色，高对比，短时置顶 |
| 中 | 前哨可重建、能量机关可触发/正在激活、飞镖闸门开启、空中支援消耗金币、敌方低血量、敌方易伤 | 黄/蓝色，进入当前告警 |
| 低 | 增益获得/失效、模块短暂异常恢复、自定义数据恢复、普通事件 | 灰/白色，仅进事件流 |

事件来源主要来自 `Event`、`PenaltyInfo`、`GlobalUnitStatus`、`RuneStatusSync`、`AirSupportStatusSync`、`DartSelectTargetStatusSync`、机器人状态和本地链路监控。

## 4. C 中央图传主视野

中央区域以图传为主，不做过多面板覆盖。图传 HUD 只保留射击和生存相关信息。

```text
┌──────────────────────────────────────────────┐
│                                              │
│                  图传画面                     │
│                                              │
│                 准星 + 热量环                 │
│                                              │
│        弹量 238     预计可射 2 发             │
│        最近弹速 18.2m/s    锁定：否           │
│                                              │
└──────────────────────────────────────────────┘
```

准星热量环：

- 环形进度 = 当前热量 / 热量上限。
- 0~60% 使用冷色。
- 60~85% 使用黄色。
- 85~100% 使用橙/红色。
- 超过热量上限或发射机构锁定时红色闪烁或断裂环。
- 可显示“预计可再射发数”：
  - 17mm 弹丸每发增加 10 热量。
  - 42mm 弹丸每发增加 100 热量。
  - 预计可射 = `floor((热量上限 - 当前热量) / 单发热量)`。

图传 HUD 建议显示：

- 准星/辅助瞄准标记。
- 当前热量环。
- 剩余允许发弹量。
- 最近弹速。
- 发射机构状态：正常、超热锁定、测速离线锁定、空中反制锁定。
- 本机 Buff：攻击、防御、易伤、热量冷却、回血。
- 被遮挡或断图传原因。

图传不可用时，不应空白。中央显示替代态势：

```text
图传不可用
原因：英雄部署模式 / 超热量 / 图传模块离线 / 判罚遮挡
自定义数据流：正常
本机坐标：x, y, yaw
可用操作：退出部署 / 等待冷却 / 检查模块
```

## 5. D 右侧角色操作区

右侧是动态角色面板，只放比赛中可能需要按的操作。所有按钮必须显示可用性、不可用原因、消耗和倒计时。

通用操作：

- 远程补血。
- 远程补弹。
- 确认复活。
- 立即复活。
- 兑换 17mm/42mm 允许发弹量，是否放主 UI 取决于机器人角色。

通用按钮状态需要显示：

- 可用/不可用。
- 不可用原因：未脱战、金币不足、读条未完成、阶段不可用、机器人战亡、前哨/补给/基地增益点条件不满足。
- 消耗：金币、弹量数量。
- 生效倒计时：远程补血/补弹 6 秒等。

角色专属操作：

| 角色 | 主 UI 右侧内容 |
| --- | --- |
| 英雄 | 部署模式状态、是否在可部署区、进入/退出部署、2 秒部署倒计时、部署导致图传断开提示 |
| 步兵 | 远程补弹/补血突出显示；若该步兵负责能量机关，显示能量机关触发状态和跳转入口 |
| 哨兵 | 当前姿态、进攻/防御/移动切换、姿态切换冷却、弱化状态、哨兵指令结果 |
| 空中/云台 | 呼叫/暂停空中支援、免费剩余时间、已花费金币、是否被雷达照射、是否被反制锁定 |
| 工程 | 开始装配、选择难度、确认装配、取消装配；完整装配进度放底部工程条 |

按钮数量建议控制在 8~10 个以内。超过后应合并为分组或移到机制页。

## 6. 工程主 UI 特化

工程操作手不应为了装配频繁切换到机制页。工程主 UI 需要在底部常驻装配流程条，右侧只保留操作按钮。

工程主 UI 结构：

```text
┌───────────────┬────────────────────────────────┬───────────────┐
│ 告警/事件      │ 图传                           │ 快捷操作       │
│               │                                │ 选择难度       │
│               │                                │ 确认/取消      │
├───────────────┴────────────────────────────────┴───────────────┤
│ 工程装配条：难度 │ 核心状态 │ 放入 │ 平移 │ 旋转 │ 四级总倒计时 │ 单步倒计时 │
└────────────────────────────────────────────────────────────────┘
```

底部工程装配条显示：

- 当前可选最高难度。
- 当前选择难度。
- 科技核心基础状态：初始、运动中、已到位。
- 能量单元放入状态。
- 平移状态。
- 旋转状态。
- 四级装配总剩余时间。
- 四级单步骤 5 秒协同倒计时。
- 对方科技核心状态。
- 最近装配结果或失败原因。

右侧工程操作按钮：

- 开始装配。
- 难度选择。
- 确认装配。
- 取消装配。

## 7. E 模块状态图标

模块状态不放长文字，使用图标矩阵。正常时低调，异常时展开原因。

```text
┌───────────────┐
│ 模块           │
│ 主控 ✓  图传 ✓ │
│ 定位 ✓  测速 ! │
│ 装甲 ✓  电容 ✓ │
│ 17mm ✓  42mm - │
└───────────────┘
```

状态颜色：

- 绿色：在线。
- 灰色：未配置或不适用。
- 黄色：安装异常，被视为离线。
- 红色：离线。
- 闪烁：刚发生变化。

异常展开示例：

- 测速离线：对应发射机构锁定。
- 定位离线：雷达标记判定受影响。
- 图传离线：视频不可用。
- 主控离线：机器人异常离线风险。

## 8. F 右下小地图

主 UI 右下放小地图是合理的。它提供最低限度战场态势，不替代完整地图页。

建议大小：

- 260x180 到 320x220。
- 可放在右侧操作区底部。
- 也可作为图传右下角浮窗，但不能遮挡准星和热量环。

小地图显示：

- 己方机器人。
- 雷达识别到的敌方机器人。
- 当前目标点和云台手标记。
- 基地、前哨站。
- 关键增益点简化图标。
- 本机朝向。
- 最近一次地图指令。

小地图不显示：

- 所有地形跨越点细节。
- 完整路径数组。
- 复杂图层控制。
- 大量文字。

交互建议：

- 主 UI 小地图默认只读。
- 支持点击放大或跳转地图页。
- 不建议在主 UI 小地图直接执行复杂地图指令，避免误触。

## 9. G 底部本机状态条

非工程角色底部显示本机状态；工程角色底部优先显示工程装配流程条。

普通底部状态：

```text
HP 260/300 │ 底盘能量 31k/40k │ 缓冲 54/60 │ 等级 6 │ 经验 3100/3300 │
Buff: 防御+25% 12s / 易伤15% │ 脱战 3s │ 无敌 8s │ 虚弱 否
```

建议显示：

- 本机血量。
- 底盘能量。
- 缓冲能量。
- 当前等级和经验。
- 攻击/防御/易伤/热量冷却/回血 Buff。
- 脱战倒计时。
- 复活后的无敌和虚弱状态。

热量和弹量不只放底部，必须在中央 HUD 附近重复显示，因为射击时操作手视线集中在准星附近。

## 10. 主 UI 信息取舍

主 UI 应显示：

- 顶部全局胜负态势。
- 双方机器人血量横条。
- 左侧当前告警和事件流。
- 中央图传、准星热量环、弹量、锁定状态。
- 右侧通用和角色操作。
- 工程装配流程，若当前是工程客户端。
- 右下小地图。
- 模块状态图标。

主 UI 不应显示：

- 完整大地图图层控制。
- 完整雷达目标分析列表。
- 全量工程机制解释。
- 全量飞镖机制细节。
- MQTT topic 调试数据。
- UDP 图传分片详情。
- 全量历史事件日志。

这些内容应放到地图 UI、机制/指挥 UI 或调试 UI。

## 11. 第一版 MVP

第一版主 UI 建议先完成：

1. 顶部状态带：比赛阶段、时间、基地、前哨站、双方机器人血量、金币、链路。
2. 左侧告警：当前告警 3 条、事件流 6 条。
3. 中央图传：准星热量环、弹量、最近弹速、锁定状态。
4. 右侧操作：补血、补弹、复活、立即复活、角色专属按钮。
5. 工程特化：底部装配流程条。
6. 右下小地图：只读态势。
7. 模块状态图标：异常时展开原因。

这个版本覆盖主操作闭环，同时保留后续扩展到地图 UI、机制 UI 和调试 UI 的空间。
