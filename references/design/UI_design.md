# RoboMaster 2026 自定义客户端 UI 设计讨论稿

来源参考：

- `RoboMaster_2026_机甲大师高校系列超级对抗赛比赛规则手册.pdf`
- `RoboMaster_2026_机甲大师高校系列赛通信协议_V1.3.0（20260327）.pdf`
- `detail.md`

本文是 UI 规划草案，不是固定规格。实际实现时应根据队伍战术、操作手习惯、屏幕尺寸、输入设备、实测信息密度继续调整。

## 1. 设计目标

自定义客户端 UI 的核心目标不是“把协议字段全部显示出来”，而是帮助操作手在高压比赛中更快完成判断：

- 当前能不能活：血量、热量、底盘能量、模块状态、Buff/易伤、判罚、图传状态。
- 当前能不能打：弹量、热量、发射机构锁定、敌方位置、敌方易伤、目标优先级。
- 当前能不能操作：补血、补弹、复活、空中支援、飞镖、能量机关、工程装配、哨兵姿态等按钮是否满足规则条件。
- 当前是否影响胜负：基地、前哨站、全队伤害、总剩余血量、关键机制窗口。

因此 UI 应按“决策价值”和“扫视频率”组织，而不是按协议 topic 或数据来源组
织。

## 2. 信息优先级

### P0：应常驻或一键可见

这些信息直接影响当下操作或胜负判断：

- 比赛阶段、剩余时间、暂停状态。
- 己方/敌方基地血量、护盾、护甲展开状态。
- 己方/敌方前哨站血量、存活/被击毁/可重建/重建中状态。
- 本机血量、热量、剩余允许发弹量、底盘能量、缓冲能量。
- 本机存活、战亡、复活读条、虚弱、脱战、被判罚、模块异常。
- 雷达或地图上的关键敌方位置、特殊标识、易伤目标。
- 关键事件：基地被攻击、前哨站被摧毁、能量机关激活、飞镖命中、空中支援、雷达反制、红黄牌。

### P1：重要，但可放在二级区域或机制页

- 己方金币、累计经济、科技等级、加密等级。
- 己方全体机器人血量、弹量、存活状态。
- 当前 Buff：攻击、防御、易伤、热量冷却、回血、地形跨越。
- 能量机关状态、机会次数、正在激活窗口、已激活剩余时间。
- 飞镖目标、闸门状态、发射窗口、检测窗口、命中收益。
- 空中支援免费时间、已消耗金币、是否被照射、是否被反制锁定。
- 哨兵姿态、姿态冷却、是否弱化。
- 工程装配状态、四级装配倒计时、对方科技核心状态。

### P2：赛前、训练、调试、复盘优先

- MQTT 连接状态、topic 收发频率、最后更新时间。
- UDP 图传帧号、分片完整率、解码延迟。
- Protobuf 解析错误、原始字段值。
- 模块详细在线状态。
- 伤害来源统计。
- 自定义控制/自定义上传数据包序号、丢包、版本。

## 3. 推荐页面结构

建议至少保留四类页面：

1. 主战斗 UI：默认页面，服务单车操作闭环。
2. 地图战术 UI：服务雷达态势、云台手标记、半自动控制和协同。
3. 机制/指挥 UI：服务金币、能量机关、飞镖、空中支援、工程装配、哨兵干预等资源决策。
4. 调试 UI：服务训练、赛前检查和故障定位，正式比赛中尽量隐藏或降低误触风险。

页面数量可以裁剪：

- 步兵/英雄单车客户端：主战斗 UI + 地图 UI + 调试抽屉即可。
- 云台手/指挥客户端：地图 UI + 机制/指挥 UI 权重更高。
- 工程客户端：主战斗 UI 中应强化装配信息，机制页应提供完整装配控制。
- 哨兵客户端：地图路径、姿态、补弹/回血/复活比普通图传信息更重要。

## 4. 全局可复用骨架

可以用一套共享骨架，但不要把布局写死：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部全局状态区：比赛阶段 / 时间 / 基地 / 前哨站 / 金币 / 告警 │
├───────────────┬──────────────────────────────┬─────────────┤
│ 左侧态势区     │ 主内容区：图传 / 地图 / 机制面板 │ 右侧操作区   │
├───────────────┴──────────────────────────────┴─────────────┤
│ 底部状态区：本机底盘、电容、模块、Buff、事件流               │
└────────────────────────────────────────────────────────────┘
```

可调整原则：

- 顶部可以同时放己方和敌方核心信息，尤其是基地、前哨站、全队血量概览。
- 左侧和右侧不必须固定。若右侧操作按钮干扰视觉或输入节奏，可以改成按键提示栏、底部按钮带、悬浮快捷面板或物理按键映射状态。
- 图传页面应优先保护视野。任何覆盖层都应可隐藏、半透明或只在状态变化时短暂出现。
- 地图页面可以使用左右面板，因为地图本身需要目标列表和指令配置。
- 调试页面可以更密集，但不要沿用到正式比赛页面。

## 5. 主战斗 UI

### 作用

主战斗 UI 解决三个问题：

- 我现在是否安全。
- 我现在是否能输出。
- 我现在是否需要按某个规则操作按钮。

它不应该承担完整指挥和完整调试职责。

### 推荐分区

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 顶部：阶段/时间 │ 己/敌基地 │ 己/敌前哨站 │ 己方金币 │ 全队血量概览 │ 告警 │
├───────────────┬──────────────────────────────────────────────┬─────────────┤
│ 队伍态势/目标   │                  图传画面                     │ 操作/按键区   │
│ 己方血量列表    │     少量 HUD：热量 / 弹量 / 锁定 / Buff         │ 补血/补弹等   │
│ 敌方简略信息    │                                              │ 或按键提示     │
├───────────────┴──────────────────────────────────────────────┴─────────────┤
│ 底部：HP / 热量 / 弹量 / 底盘能量 / 缓冲 / 模块 / Buff / 最近事件          │
└────────────────────────────────────────────────────────────────────────────┘
```

### 顶部全局状态区

建议放最高价值、低解释成本的信息：

- 比赛阶段与剩余时间。
- 己方基地血量、护盾、护甲展开状态。
- 敌方基地血量、护盾、护甲展开状态。
- 己方前哨站状态。
- 敌方前哨站状态。
- 己方金币。
- 己方全体机器人简略血量条。
- 当前最高优先级告警。

说明：

- 将己方和敌方信息放到主 UI 顶部是合理的，尤其适合需要兼顾战术判断的客户端。
- 若顶部信息过载，可以只常驻基地/前哨站，机器人全队血量改为折叠条或图标条。
- 时间和基地状态不建议移出顶部，因为它们直接影响胜负优先级。

### 中央图传区

中央应以图传为主，叠加信息保持克制：

- 准星或视觉辅助。
- 当前热量与热量上限。
- 剩余允许发弹量。
- 上一发弹速或射击状态。
- 发射机构锁定状态。
- 当前关键 Buff 或易伤。
- 图传断开原因提示：超热量、英雄部署、罚下、链路异常等。

热量和弹量可以有两种布局：

- 放在图传中下方：便于射击时扫视。
- 放在底部大状态条：减少遮挡。

具体选哪种应根据操作手反馈决定。

### 左侧态势区

可选内容：

- 己方英雄、工程、步兵、哨兵血量。
- 存活/战亡/复活读条。
- 队友关键状态：脱战、虚弱、模块离线、被罚。
- 敌方简略血量或雷达目标列表。

调整建议：

- 单车操作型客户端：左侧优先放己方队友状态。
- 指挥型客户端：左侧可混合敌方目标优先级。
- 如果顶部已经放了所有人血量，左侧可以改成目标/事件列表。

### 右侧操作区或按键提示区

这里不一定要放大按钮。可根据真实操作方式调整：

方案 A：可点击操作面板。

- 远程补血。
- 远程补弹。
- 确认复活。
- 立即复活。
- 英雄部署模式。
- 哨兵姿态。
- 空中支援。
- 飞镖相关确认。

方案 B：按键提示面板。

- 显示当前物理按键绑定。
- 显示操作是否可用。
- 显示不可用原因，如未脱战、金币不足、读条未完成、冷却中。
- 不提供鼠标点击，避免和视觉/瞄准/操作干扰。

方案 C：折叠/弹出面板。

- 平时只显示 3-5 个关键状态。
- 按住某个键时展开完整操作。
- 松开后自动收起。

推荐：

- 对高频战斗页，右侧更适合作为“按键状态和可用性提示”，不一定作为鼠标操作区。
- 对地图/机制页，右侧更适合做可点击操作区。

### 底部本机状态区

适合放本机细节：

- HP。
- 热量。
- 弹量。
- 底盘能量。
- 缓冲能量。
- 当前经验和等级。
- 当前 Buff 及剩余时间。
- 模块状态小图标。
- 最近 3-5 条事件。

底部状态适合持续存在，但不应太高，以免压缩图传。

## 6. 地图战术 UI

### 作用

地图页服务协同：

- 观察己方、敌方、目标和增益点。
- 发云台手地图标记。
- 给半自动控制机器人发送目标点。
- 利用雷达信息判断集火、避战、转点。

### 推荐分区

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 顶部：阶段/时间 │ 基地/前哨站 │ 金币 │ 全队血量 │ 雷达/地图告警          │
├───────────────┬──────────────────────────────────────────────┬─────────────┤
│ 目标列表       │                    全场地图                   │ 地图指令区   │
│ 敌方状态       │  机器人 / 雷达点 / 增益点 / 路径 / 标记          │ 标记/发送     │
│ 特殊标识       │                                              │ 目标/范围     │
├───────────────┴──────────────────────────────────────────────┴─────────────┤
│ 底部：图层开关 │ 点击坐标 │ 上次发送 │ 发送冷却 │ 地图事件                 │
└────────────────────────────────────────────────────────────────────────────┘
```

### 中央地图

默认显示：

- 场地边界。
- 己方机器人。
- 雷达敌方位置。
- 基地、前哨站。
- 关键增益点：补给区、基地增益点、前哨站增益点、堡垒、装配区、中央高地。
- 云台手标记。
- 哨兵路径。

可选图层：

- 地形跨越点。
- 飞镖目标和引导灯状态。
- 能量机关状态。
- 历史轨迹。
- 雷达数据更新时间/可信度。

地图显示建议：

- 默认不要把所有增益点都做成高亮，容易看不清机器人。
- 高价值状态才强提示：敌方易伤、基地护甲展开、前哨站可重建、堡垒占领计时。

### 左侧目标列表

适合显示：

- 敌方机器人 ID/类型。
- 最新坐标时间。
- 是否特殊标识。
- 是否易伤：15%、20%、双倍易伤。
- 血量，若可获取。
- 目标优先级。

也可以放己方目标任务：

- 谁去补给。
- 谁去重建前哨。
- 谁负责能量机关。
- 谁接收地图指令。

### 右侧地图指令区

适合放：

- 标记类型：攻击、防御、警戒、自定义。
- 目标模式：地图点、敌方机器人。
- 发送范围：指定客户端、除哨兵、包含哨兵。
- 目标机器人列表。
- 半自动指令：移动、攻击、防守。
- 发送按钮。
- 发送冷却。

重点：

- 云台手地图发送间隔至少 0.5s。
- 半自动控制方式的机器人通过大地图发送间隔至少 3s。
- UI 应明确显示冷却，避免操作手误以为指令没发出去。

## 7. 机制/指挥 UI

### 作用

机制页负责“资源和特殊机制决策”，适合云台手、工程、指挥型客户端使用。

### 推荐分区

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 顶部：阶段/时间 │ 金币 │ 科技等级 │ 加密等级 │ 基地/前哨站 │ 告警        │
├────────────────────────┬────────────────────────┬────────────────────────┤
│ 经济/兑换               │ 能量机关                │ 飞镖/空中               │
│ 发弹量/回血/复活         │ 状态/机会/收益           │ 闸门/目标/支援           │
├────────────────────────┼────────────────────────┼────────────────────────┤
│ 工程装配                │ 哨兵控制                │ 全局事件/战术提示         │
│ 难度/步骤/倒计时         │ 姿态/补给/复活           │ 前哨/堡垒/收益            │
└────────────────────────┴────────────────────────┴────────────────────────┘
```

### 经济/兑换

显示：

- 当前金币。
- 17mm/42mm 兑换状态。
- 远程补弹条件。
- 远程回血条件。
- 立即复活价格。
- 空中支援付费消耗。
- 本机或选中机器人是否满足操作条件。

按钮应显示不可用原因：

- 金币不足。
- 未脱战。
- 不在对应增益点。
- 已达兑换上限。
- 复活读条未完成。

### 能量机关

显示：

- 当前小能量机关/大能量机关阶段。
- 可触发机会次数。
- 正在激活 20s 窗口。
- 已激活剩余时间。
- 激活灯臂数。
- 平均环数。
- 当前攻击、防御、热量冷却收益。

操作：

- 触发能量机关。
- 显示触发是否可用。

### 飞镖/空中

飞镖显示：

- 剩余飞镖。
- 闸门开启机会。
- 当前目标。
- 闸门状态：关闭、开启中、已开启。
- 30s 发射窗口。
- 40s 检测窗口。
- 发射确认状态。

空中显示：

- 是否正在空中支援。
- 免费支援剩余时间。
- 已消耗金币。
- 是否被激光照射。
- 发射机构是否被雷达反制锁定。

### 工程装配

显示：

- 当前可选最高难度。
- 当前选择难度。
- 科技核心基础状态：初始、运动中、到位。
- 放入状态。
- 平移状态。
- 旋转状态。
- 四级装配总剩余时间。
- 单步骤协同剩余时间。
- 对方科技核心状态。
- 最近装配事件。

操作：

- 开始装配。
- 确认装配。
- 取消装配。

### 哨兵控制

显示：

- 自动/半自动控制方式。
- 当前姿态：进攻、防御、移动。
- 姿态冷却。
- 姿态累计时间。
- 是否弱化。
- 上次指令结果。

操作：

- 补血点补弹。
- 补给站实体补弹。
- 远程补弹。
- 远程回血。
- 确认复活。
- 花费金币复活。
- 切换姿态。

## 8. 调试 UI

### 作用

调试 UI 服务赛前、训练和故障定位，正式比赛中应避免误触。

### 推荐分区

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ clientID │ MQTT │ 视频 │ server/local IP │ 当前机器人 │ 当前阶段            │
├────────────────────────┬────────────────────────┬────────────────────────┤
│ Topic 监控              │ 图传/自定义数据          │ 原始状态/日志            │
│ 频率/更新时间/错误       │ UDP帧/分片/延迟           │ 模块raw/事件/操作日志     │
└────────────────────────┴────────────────────────┴────────────────────────┘
```

显示：

- MQTT 连接状态。
- 当前订阅 topic。
- 各 topic 接收频率。
- 最后更新时间。
- Protobuf 解析错误。
- 发送频率和本地节流。
- UDP 帧号。
- 分片完整率。
- 解码延迟。
- `CustomControl` 发包序号。
- `CustomByteBlock` 接收序号。
- 模块状态原始值。
- 最近事件日志。

## 9. 可调整项清单

这些内容不应在第一版设计中写死：

- 己方和敌方信息是否都放在主 UI 顶部。
- 全队血量放顶部、左侧还是底部。
- 敌方信息放主 UI、地图 UI，还是只在指挥 UI 显示。
- 右侧是否是鼠标点击操作区，还是只做按键状态显示。
- 热量/弹量放图传覆盖层还是底部大状态条。
- 地图默认显示哪些图层。
- 机制页是否按角色拆分，或统一成一个指挥页。
- 调试页是否可在比赛中打开。
- 不同机器人类型的默认页。
- 快捷键和物理输入设备映射。

## 10. 第一版落地建议

建议先做稳定的四页：

1. 主战斗 UI：图传、本机状态、基地/前哨站、全队简略状态、关键操作可用性。
2. 地图战术 UI：全场地图、雷达位置、标记、半自动指令、图层控制。
3. 机制/指挥 UI：经济、能量机关、飞镖、空中、工程、哨兵。
4. 调试 UI：链路、topic、图传、自定义数据、日志。

随后按训练反馈调整：

- 如果操作手经常看顶部队友血量，则保留；如果干扰图传，则压缩成图标条。
- 如果鼠标点击按钮影响瞄准或操控，则改为按键提示和物理按键触发。
- 如果地图页使用频率高，则给地图页保留更多全局状态；如果只偶尔使用，则让主 UI 做小地图摘要。
- 如果机制页信息太多，按角色拆分：工程、云台/飞镖/空中、哨兵。

最终目标是让每个页面只回答一个主要问题：

- 主战斗 UI：我现在怎么活、怎么打。
- 地图战术 UI：队伍现在怎么协同。
- 机制/指挥 UI：资源和特殊机制现在该不该用。
- 调试 UI：系统为什么不对。
